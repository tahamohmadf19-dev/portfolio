RAG Quality Lab

When a team changes a RAG system, it is hard to tell whether answers improved, or why one answer cited the wrong source.

Status
Prototype, not deployed.
Source
Private repository. Walkthrough on request.
Stack
Python, FastAPI, Celery, SQLAlchemy, Pydantic, TypeScript, React

My role

My personal project: I added this layer to Onyx Community Edition. Onyx provides the platform, including its chat pipeline and connectors. The private repository is a derivative of it, and credits it in UPSTREAM.md. Its top-level README still needs to say so before any public release.

How it works

This diagram follows the real path through the code. Select a stage to read what happens there. Stages marked with a diamond are control points, where the system checks, stops or waits for a person.

Engineering decisions

  • Separated what is measured from what is judged. An LLM judge cannot change a deterministic score.
  • Treated "not measurable" as different from zero across the metrics, API and interface.
  • Called the platform's existing chat pipeline for evaluation instead of writing a test-only copy.
  • Kept the prompt-injection and credential detectors narrow, to limit false alarms.

What was tested

  • Evaluation: 122 passed. Metrics 48, aggregation 17, judge 26, runner 27, dispatch 4.
  • Knowledge operations and ingestion security: 70 passed.
  • Retrieval debugger: 37 passed. Citation privacy: 7 passed.
  • Frontend: 175 passed in 17 suites, 106 of them for the evaluation dashboard and debugger.
  • Run at commit c28ad87 from a clean copy with the project's own environment. The database, LLM and Celery broker were replaced by fakes.

Limits and open work

  • Never run end to end against the full platform in this check, so the real chat path is untested.
  • No evaluation report on a real document collection yet.
  • This is an extension of Onyx, not an independent RAG platform.
  • The dashboard has not been viewed running.
