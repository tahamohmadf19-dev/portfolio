EduSmartAI

An academic platform needed to warn about struggling students early, but its old 0.979 score relied on data only known after a course ended.

Status
Branch not merged. PR #7 was closed with no review.

Stack
Python, FastAPI, scikit-learn, SQLAlchemy, PostgreSQL, React

My role

EduSmartAI is a graduation project by @bahaaed07706, who built and owns it. He had already documented that the old 0.979 was inflated by leakage, and he wrote the retriever. My branch builds the replacement models and the backend hardening around them. Its commits credit an AI coding agent as co-author.

This diagram follows the real path through the code. Select a stage to read what happens there. Stages marked with a diamond are control points, where the system checks, stops or waits for a person.

Engineering decisions

  • Reported that the day-14 model is close to chance, and called it insufficient for operational use, instead of tuning until it looked better.
  • Built replacement models after the project owner documented the leakage in the old 0.979.
  • Added server-side token revocation, audit logging and rate limiting to the backend.
  • Added a bilingual held-out RAG evaluation, Arabic right-to-left support and accessibility work.

What was tested

  • Retrained with scripts/train_early_risk.py on 2026-11-07.
  • ROC-AUC by cut-off: day 14, 0.5657. Day 28, 0.6769. Day 42, 0.7288.
  • Accuracy by cut-off: day 14, 0.5536. Day 28, 0.6444. Day 42, 0.6844.
  • Backend suite: 220 passed, 3 skipped, at commit 73583aa.

Limits and open work

  • The legacy 0.979 could not be reproduced, because a source file is not in the repository.
  • The branch is not part of the project's main branch.
  • The retriever is by the project owner, and it is lexical, not semantic.
  • Live LLM answer quality was not evaluated. Frontend tests and the live PostgreSQL integration were not run.
