RAG evaluation

Prototype

RAG Quality Lab

When a team changes a RAG system, it is hard to tell whether answers improved, or why one answer cited the wrong source.

What I built

  • An evaluation and debugging layer added to Onyx Community Edition, an open-source RAG platform.
  • Versioned test datasets, background runs and saved results for each test case.
  • Six retrieval and citation metrics, plus an optional LLM judge that cannot change them.
  • An admin dashboard, a read-only retrieval debugger, and rule-based checks for risky text in ingested documents.

What works

  • Metrics leave a value undefined when it cannot be measured, instead of counting it as zero.
  • A failed test case is saved and the run continues.
  • If the judge fails, the case still succeeds with an empty judge score.

Architecture and stack

Python and FastAPI services inside Onyx, Celery for background runs, SQLAlchemy migrations, and React admin pages.

Python, FastAPI, Celery, SQLAlchemy, Pydantic, TypeScript, React

Evidence

  • Ran All 411 unit tests I added passed on 2026-11-07: 236 backend and 175 frontend, with the database, LLM and task broker replaced by fakes.
  • In code Migrations, API routes and dashboard pages are in the code. The pages have not been viewed running.
  • Not done Not run end to end, and not evaluated on a real document collection.
Status
Prototype, not deployed.

Unmerged contribution

EduSmartAI

An academic platform needed to warn about struggling students early, but its old 0.979 score relied on data only known after a course ended.

What I built

  • On a branch of a graduation project by @bahaaed07706: early-risk models for day 14, 28 and 42, using only data visible by that day.
  • Student-grouped validation, a temporal holdout and confidence intervals.
  • Shared feature code for training and serving, rule-based explanations and intervention tracking.
  • Token revocation, audit logging, rate limiting, and a PostgreSQL path.

What works

  • Models retrained from the branch reproduce its reported results.
  • ROC-AUC rises from 0.566 at day 14, close to chance, to 0.729 at day 42.
  • Backend security, intervention and serving behavior pass their tests.

Architecture and stack

FastAPI and SQLAlchemy backend, scikit-learn pipelines per cut-off, and a React frontend with Arabic and English.

Python, FastAPI, scikit-learn, SQLAlchemy, PostgreSQL, React

Evidence

  • Ran Retrained on 2026-11-07: ROC-AUC 0.566, 0.677 and 0.729, matching the report.
  • Ran Backend tests: 220 passed, 3 skipped, at commit 73583aa.
  • In code Frontend tests and the live PostgreSQL integration were not run.

About

I am an AI Engineer in Amman with a B.Sc. in Data Science and Artificial Intelligence from Philadelphia University. The part of AI work I care about most starts after the first demo: can it be measured, can it be stopped, and what happens when something fails?

That is why my projects look the way they do. They track evidence, separate tenants and wait for approval. Most of them build on existing software instead of starting from nothing, and each one says so. I also use AI coding agents in my work, and the project pages say where that is known.

How I work

  • Measure before claiming

    Evaluation comes with the system, and a missing measurement stays missing. See RAG Quality Lab

  • Keep authority out of the model

    Scope and permissions live in server code, where a prompt cannot change them.

  • Give automation a stopping point

    Risky steps wait for a check or a person, and retries cannot repeat them.

  • Report what the data supports

    When a strong number comes from a flawed test, I replace it and explain why. See EduSmartAI
